# 文首会议元数据识别技术设计

## 目标

处理文首同一物理段落中的“主标题 → 括号日期 → 会议说明”软换行结构：

1. 结构证据充分时，拆为主标题、会议标题元数据、会议标题元数据三个逻辑块；日期是标题结束边界，不再作为标题续行。
2. 两个会议标题元数据块使用现有作者行/职务名称的样式规则：楷体_GB2312、三号、加粗、居中。
3. 不使用具体机构、人名、地域或用户样稿全文作为识别条件。

## 非目标

- 不改变会议纪要正文中“出席：”“议题：”等既有 `meeting_meta` 的正文型格式。
- 不改变普通文首日期行、署名行、职务姓名或正文的既有语义与格式。
- `strict` 模式继续保留物理段落，不因本规则新增逻辑拆分。
- 结构证据不足时不强行拆分，也不把整个复合块伪装成主标题。

## 已核实事实

- 软换行拆分由 `document/segmentation/soft_breaks.py` 决定；未命中时会保留整个物理段。
- 最终 authoritative decoder 会覆盖旧 importer 的弱标题候选，因此单个混合多行块可能最终成为正文。
- 现有 `meeting_meta` 已用于会议纪要正文键值字段，当前映射到正文样式，不能复用为文首会议说明。
- 作者行和职务名称共享楷体_GB2312、三号、加粗、居中的现有配置规则。

## 设计

新增独立最终类型 `meeting_title_meta`，仅表示主标题后的会议日期或短会议说明。

```text
物理段软换行
  → 通用“标题 + 日期 + 会议说明”结构校验
  → logical segments
  → 文首上下文标记 meeting_title_meta
  → authoritative candidate / hard veto
  → meeting_title_meta
  → 作者行样式规则与 DCT-Author 样式
```

### 分段条件

仅在 structural/smart 路径中、且同时满足下列条件时拆分：

- 日期前存在短、非句式的标题行；
- 日期行是完整的括号年份日期；
- 日期后是短、非句式的会议场景说明，例如“在……会议上”的通用形态；
- 不存在编号、冒号键值、正文终止标点或长正文等反证。

分段后必须保持文字、物理锚点、UTF-16 范围和 source span 完整守恒。

### 识别与样式契约

- 标题前的行按既有主标题/标题续行规则处理。
- 满足“标题 + 日期 + 会议说明”完整上下文的日期和会议说明均标记为 `meeting_title_meta`；这使两行都使用用户指定的加粗楷体格式。
- 新类型使用 `SectionKind.HEADER`，禁止再被候选为主标题或标题续行，也不进入正文流。
- 渲染复用作者行的配置行和 `DCT-Author`，不新增配置字段、格式设置 UI 或第二套字体常量。

## 失败边界

- 只有完整结构证据才触发；普通多行正文、普通日期行、普通作者/职务行和会议纪要键值行不升级。
- 无法安全判断时不建立错误边界，也不把多行复合块整体归为主标题。
- 若后续发现还需要按单个 run 在未拆分物理段内应用不同类型格式，须先单独设计渲染层的范围格式契约；本次不暗中引入该能力。

## 验收

- 安全的文首三行软换行产生 `title / meeting_title_meta / meeting_title_meta`。
- 新类型不会被 authoritative decoder 覆盖成 `body` 或 `title`。
- 普通日期、普通多行正文、会议纪要正文键值和职务/署名现有回归保持不变。
- 新类型映射到作者行样式规则，并在 DOCXTOOL 与 WPS builtin profile 下保持其直接格式。
- 运行聚焦的分段、decoder、样式和结构测试，以及 Ruff、compileall、`git diff --check`。

## 停止条件

若通用形态不能区分会议说明与正文，或必须改动 strict 模式/物理锚点契约，停止实现并先补充针对性设计，不以关键词白名单或整段标题 fallback 代替。
