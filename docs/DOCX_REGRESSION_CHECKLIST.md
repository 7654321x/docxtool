# 公文排版问题清单与回归测试重点

本文档汇总项目实际遇到过的 DOCX 识别、结构拆分和导出问题。以后修改识别或排版逻辑、执行“全部测试”或准备发布时，除检查测试命令是否通过外，还必须按本清单核对结构报告和渲染页面。

清单只记录可复用的结构形态，不记录具体人员、用户文件正文或私有单位名单。

## 一、最高优先级验收

- [ ] 原文可见文字不丢失、不重复；允许的日期、标题句号、序号和附件格式规范化必须单独记录。
- [ ] 原文段落顺序保持不变；唯一允许的尾部整理是“附件说明及附件项 → 落款单位 → 成文日期”。
- [ ] 输出 DOCX ZIP、关系、图片、表格、页眉页脚和分节完整，可以被 Word、WPS 和 LibreOffice 打开。
- [ ] 标题、正文、称呼、落款、附件没有因软换行、分页符或源样式错误而互相继承格式。
- [ ] 标准 50 篇和 `test_docx/test2/test2` 专项集全部处理；报告、渲染图和疑似空白页清单写入新的批次目录。
- [ ] “处理成功”只表示文件生成成功，不能代替结构、模板差异和视觉检查结论。

## 二、标题与正文边界

### 1. 行内标题和正文

- [ ] `一、标题。正文`等同一物理段落应拆成一个标题和一段完整正文。
- [ ] 拆分后正文不得因后续句号、加粗、字体变化再次分成两段或多段。
- [ ] 标题和正文之间不得残留软换行、制表符、手动分页符或真实空段。
- [ ] 二级标题后紧接正文时，标题按二级标题格式，句号后的正文恢复普通正文格式，不能整段加粗。
- [ ] 标题后还有独立称呼、日期、附件或落款时，只拆出有强结构证据的附加段，正文自身仍只有一段。

### 2. 正文中的行内强调

- [ ] 正文首句加粗、后续普通格式时保持同一个正文段，只恢复源文件中的首句强调。
- [ ] 正文中多次字体或粗体切换不得自动生成标题或新段落。
- [ ] `一是/二是/三是`、`一要/二要/三要`仅加粗各自引导句，句号后的说明文字必须恢复普通正文。
- [ ] 普通句号不能作为正文拆段依据。

### 3. 主标题与层级标题

- [ ] 文首“在……上的讲话”等标题即使误用 Word `Heading 1`，仍应识别为主标题，不得自动生成“一、”。
- [ ] 多行主标题、标题续行、职务姓名和头部日期可以缺项，但顺序和格式必须正确。
- [ ] Word `Title/Heading 1-4`仅作为弱证据；正文位置、编号、同级标题族和上下文结构优先。
- [ ] 源文件自动列表编号仅存在于 `w:numPr` 时，短加粗标题仍应保留正确层级。
- [ ] WPS 原生列表的 `ilvl=0` 短段后紧接明确的字面二级标题，且该二级标题缺少父级时，应将前段恢复为一级标题；该父子层级证据不要求前段加粗，普通 `ilvl=0` 列表项不得全局升级。
- [ ] 全文存在同级兄弟标题时应互相印证；单独编号标题证据不足时进入复核，不能靠样式强行确定。
- [ ] 一级至四级标题分别使用“一、”“（一）”“1.”“（1）”，不得重复编号、层级跳跃或把三级半角点改成中文句号。
- [ ] 独立行的`二.标题`、`三．标题`等损坏中文一级序号仍应作为一级标题证据；开启序号规范后重建为`二、标题`、`三、标题`，不得先被标点转换成正文句号。
- [ ] 开启序号规范时只替换标题前缀，不改标题正文；关闭时保留原编号。
- [ ] 独立一级标题末尾的句号应删除；其他层级和正文标点按配置处理。

## 三、称呼、机构标签与键值段

- [ ] 文首主送机关和独立个人称呼应识别为 `recipient/addressing`。
- [ ] “姓名或职务 + 书记、主席、主任、局长、老师、同志等称谓 + 冒号/感叹号”按独立称呼识别，不维护具体人名名单。
- [ ] 正文区的“机构名称：”是无首行缩进正文标签，不得误判为文首主送机关。
- [ ] “机构名称：后接正文内容”必须保持一行、一个正文段，不能在冒号处拆成两段。
- [ ] “责任单位：内容”“联系人：内容”“联系电话：内容”等键值段保持一个段落；标签加粗、值不加粗。
- [ ] 多条键值内容使用软换行时，各行统一对齐，第二行及以后不能顶格或变成独立空段。

## 四、职务姓名、落款和日期

- [ ] 文首较长的“职务 + 连续空格 + 2—4 字姓名”只有在前接标题或后接日期/称呼等结构锚点支持时才识别为 `role_name`；含角色词的报告、总结、方案和普通正文不得误判，不能依赖具体姓名。
- [ ] 职务姓名与标题、日期被软换行粘在同一段时，应拆为独立结构行，不得继承正文样式。
- [ ] 落款单位识别使用文尾位置、单位后缀、常见机构简称、后接日期等组合证据；不得擅自把简称扩写为全称。
- [ ] 正文末尾通过多个软换行、制表符或分页符粘连落款单位时，只拆出最后的单位行，前方正文保持一段。
- [ ] 同一物理段同时包含“编号标题 + 正文 + 末行落款单位”时，标题正文拆分后仍必须继续拆出落款单位。
- [ ] 下一物理段以成文日期开头时，应作为前一段末行落款单位的反向验证证据。
- [ ] 中文或混合数字成文日期统一为阿拉伯数字形式，例如 `2025年10月15日`。
- [ ] 最终落款单位必须紧邻成文日期；附件、空段或其他内容不得插在二者之间。
- [ ] 批量报告的“落款连续性问题数”必须为 `0`；审计还要发现落款单位仍粘在正文末尾的情况。

## 五、附件结构

- [ ] 尾部固定顺序为“正文 → 附件说明及附件项 → 落款单位 → 日期 → 附件正文页”。
- [ ] 源文件出现“落款单位 → 日期 → 附件说明”时，非 `strict` 模式应整理为标准尾部顺序。
- [ ] 日期、附件说明、附件项和附件正文页被软换行粘在一个物理段落时，应完整拆分且不丢文字。
- [ ] `附件：1.材料`和续项`2.材料`不得因标点规范化失去编号结构。
- [ ] 附件说明首项和续项分别使用 `DCT-AttachmentNote`、`DCT-AttachmentNoteItem`；续项之间不得多出一行。
- [ ] 附件页标识、附件标题和附件正文分别识别；附件标题段前段后各一行，不插入真实空段。
- [ ] 附件标题页内容较少时不能直接判为空白页。

## 六、版头与发文字号

- [ ] 版头开关开启时，按当前机关、文号、签发人配置重建版头；关闭时不新增、不替换已有版头。
- [ ] 关闭版头且识别到不完整外部版头时，只在可靠发文字号或签发人后补缺失红色分割线。
- [ ] 自动识别机关发文标志、结构化发文字号、签发人和分割线；缺少分割线时不能把普通正文误当版头。
- [ ] 正文中引用其他文件文号不能触发版头检测。
- [ ] 红色标题、大字号标题、图片或单个红字不能单独作为版头证据。
- [ ] 版头只插在首页首个标题前，不创建新分节，不改变全局页边距、页面尺寸和文档网格。
- [ ] 联合发文机关增删和排序后，主办机关、签发人及单一/联合模式保持一致。

## 七、标点与编号规范化

- [ ] 中文语境中的逗号、句号、冒号、分号、问号、叹号、括号和引号按中文全角形式处理。
- [ ] 三级序号`1.`、时间`11:00`、小数、英文、网址、邮箱和页码保留规定的半角形式。
- [ ] 数字两侧的时间或比例冒号（如`11:00`、`1 : 2`）即使夹有普通空格、Tab、NBSP、全角空格或其他 Unicode 空白，也不得触发冒号标签、解释性正文或标签加粗；`时间 ： 11:00`仍按第一个语义冒号识别键值结构。数字冒号后再出现标签时，只加粗真实标签和语义冒号；识别与渲染必须共享原文 offset 及标签范围逻辑。
- [ ] `时间11:00 标签：内容`、`版本1:2 标签：内容`等带文字前缀的数字表达必须返回真实标签起点；前缀和数字表达保持普通字重，只加粗`标签：`。
- [ ] `4..标题`等重复句点可安全折叠，但不得把结构编号改成`4。标题`。
- [ ] 标点修复关闭时不得改变普通文本；开启时也只能执行安全、可解释的转换。
- [ ] 标点、日期和序号规范化不得被误报为文字丢失，但报告必须记录为预期规范化。

## 八、分页、间距和页面结构

- [ ] 正文中的人工分页符如果模板和结构不需要，应移除，避免正文中产生异常空白页。
- [ ] 一级标题不写入 `keepNext/keepLines`，允许标题位于页末，避免强制带走下一段形成大片留白。
- [ ] 职务姓名、落款、附件说明和标题间距使用段前段后，不依赖真实空段。
- [ ] 标准页面上边距 `3.7 cm`产生的正常留白不能误判为故障。
- [ ] 奇偶页外侧页码不得在页脚留下额外空段，避免偶数页少排一行。
- [ ] 16 pt 正文、15.6 cm 版心和每行 28 字的文档网格在 WPS 中不得退化为 27 字或 42 字。
- [ ] 横向分节必须旋转物理页边距，并按每节实际版心重新计算文档网格。
- [ ] 渲染报告标记的空白页、稀疏页、附件标题页必须人工区分，不能仅凭文字量自动判失败。

## 九、表格、图片和题注

- [ ] 表格默认原样透传，不擅自修改字体、列宽、边框、行高或对齐。
- [ ] 表格 XML 引用的关系、样式及继承链必须完整复制；关系缺失时中止导出。
- [ ] 表格单元格依赖源默认样式时，必须使用隔离样式，不能回退到输出正文 `Normal`。
- [ ] 零尺寸 DrawingML 残留不能让含文字段落被误判为纯图片。
- [ ] 纯表格或纯图片后的第一行题注受保护；混合“正文文字 + 行内图片”不能错误保护下一段。
- [ ] `object_caption`保持独立题注语义，不得作为图片边界吞掉题注文字。
- [ ] 题注文字、字体、字号、对齐和关系资源保持不变，仅段前段后统一为 0。

## 九-A、附件分页与同行落款

- [ ] 正文尾部同一可见行中的“短组织落款 + 日期后缀”必须拆成独立落款单位和日期，日期不得残留在正文软换行中。
- [ ] 已进入附件正文区后，每个独立“附件 N”都重新开启附件页；上一附件只有标题、没有正文时也不能吞掉下一附件标记。
- [ ] 附件页标记后的短独立行可识别为附件标题；长文本或多行文本直接识别为附件正文。
- [ ] 每个 `attachment_page_mark`只写入一次段前分页，连续附件不得同页，也不得因重复分页产生额外空页。
- [ ] 标准集 008、028 必须逐页复核附件 1、2、3 的起页位置，并与正确模板的尾部顺序对照。

## 十、结构保真模式与 SDK

- [ ] `smart`必须映射为`structural`，只拆可靠结构并执行用户明确开启的功能。
- [ ] 文首全文分析已确认的职务姓名和日期时间地点必须压过继承的标题视觉样式及“主标题 → 标题续行”路径加分；只接受结构元数据，不接受旧类型或 Word 样式单独触发。
- [ ] 职务姓名识别组合使用通用职务形态、2—4 字姓名后缀、文首位置及后接日期或称呼，不维护具体姓名、单位、地区或样稿白名单；真实副标题中的职务词不得误判。
- [ ] 普通四字纯汉字姓名后缀按弱形状处理，只有“前标题 + 后日期/称呼 + 居中”同时成立才确认；复姓、间隔点、占位符和 2—3 字姓名保留强形状。紧凑职务姓名必须优先选择强姓名切分。
- [ ] `strict`完全保留物理段落；`normalize`才允许旧式文字、标点和编号规范化。
- [ ] `smart`不得静默改写未启用的正文文字、段落顺序或编号。
- [ ] 每次结构拆分后，所有子范围完整覆盖原物理段落可见文字，不重叠、不丢失。
- [ ] Wheel/SDK 使用物理段落哈希、重复出现序号、UTF-16 子范围和子范围哈希定位，不能把逻辑块序号当作 WPS 段落序号。
- [ ] 尾部重排后，SDK block 数组可保持最终排版顺序，但同一物理段落的分片序号、重叠核验和绑定顺序必须按原始 UTF-16 范围排序；落款、日期和附件分片均应通过范围回读。
- [ ] 混合结构段落在 WPS 正式修改前必须要求拆分，不能使用不可靠的裸序号回退定位。

## 十一、DOCX 完整性与安全边界

- [ ] 重复 ZIP 成员、缺失关系目标和无法迁移的资源必须拒绝，不能生成表面可打开但内容缺失的文件。
- [ ] 损坏关系修复产生的临时文件必须清理。
- [ ] 外部 OOXML 关系按允许范围处理，不能无条件复制危险外部对象。
- [ ] 报告只记录段落号、类型、长度、证据和文字哈希，不记录完整正文、密钥、Cookie 或用户身份信息。
- [ ] 原件、成功结果、失败任务文件和任务记录按项目永久保留策略处理，不得在测试中覆盖或删除。
- [ ] WPS 的预览排版和一键排版共用同一个格式前置入口；旧 `.doc/.wps` 只允许 WPS Host 对隐藏临时文件执行一次 `SaveAs2(..., 12)`并永久升级为同名 `.docx`。预览原样发布转换结果后继续 SDK 识别，一键排版复用转换桥接文件进入 Core；本机检测不转换，旧格式清除预览返回 0。同名 `.docx` 已存在时不得覆盖；新 DOCX 重开前必须保留旧源文件和可恢复备份，失败后恢复旧源文件并清理临时文件。

## 十二、每轮测试执行顺序

1. 运行相关识别、结构拆分、导出和审计单元测试。
2. 运行全量 Python 测试与 Ruff；涉及前端或 Worker 时同时运行 Node 测试。
3. 处理 `test_docx/tset1/test1` 全部 50 篇，并按编号匹配 `test_docx/tset1/test1正确格式` 模板进行区域保序对齐。
4. 处理 `test_docx/test2/test2` 全部专项稿，必要时参考 `test_docx/test2/test2正确格式`，不使用无关模板强行比较。
5. 检查批量报告中的失败数、P0、文字新增/丢失、源标题线索未保留、结构复核和落款连续性。
6. `strict/normalize`的预期模式差异必须保留原始差异类别和数量；只有规范化后字符守恒且结构符合模式契约时才排除出真实 P1/P2。
7. 渲染专项集全部文档和标准集确定性抽取的 10 篇，逐页查看疑似空白页、分页、标题、附件和落款。
8. 对本轮直接修复的问题，必须打开对应原稿和输出稿对照，确认实际页面已修复，不能只看单元测试。
9. 在 WPS 中抽查文档网格、页码、表格和分页等 LibreOffice 可能表现不同的项目。

当前长期专项目录已经迁移到 `test_docx/test2/test2`；历史 `test_docx/测试文稿/测试目录` 仅作为旧空目录记录，不再写入新的测试结果。

模板差异必须按“国标明确规则 → 当前版本配置 → 旧模板实现”分层判断。标题对齐先剥离一至四级编号和允许规范化的一级标题句号，再比较标题正文与层级；输入、输出和模板执行三方归因，原稿已有顺序或内容差异不得记为输出新增/丢失。缩进优先读取 OOXML 的`firstLineChars/leftChars/rightChars`并按字符值容差比较，不比较等效的 twip/EMU 整数。受保护表格或图片题注的字体、字号和斜体只核对输出是否保持原稿，不因旧模板不同而要求改写。

推荐命令：

```pwsh
pwsh -NoProfile -Command ".\.venv\Scripts\python.exe -m pytest -q"
pwsh -NoProfile -Command ".\.venv\Scripts\python.exe -m ruff check src tests scripts"
pwsh -NoProfile -Command ".\.venv\Scripts\python.exe scripts/batch_test_docx.py --output-dir test_docx/tset1/test1测试结果/<新批次> --special-output-dir test_docx/test2/测试结果/<新批次> --render-review --require-render"
```

## 十三、报告结论用语

- 可以说：“55 篇均成功生成，目标问题审计为 0，已完成指定页面视觉复核。”
- 不应仅因文件生成成功就说：“所有格式都没有问题。”
- 模板仍存在真实 P1/P2 差异时，应明确说明差异数量和是否属于本轮目标。
- 渲染器未运行时，应明确说“未执行视觉检查”，不能断言没有空白页或分页问题。
